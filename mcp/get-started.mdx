<Tabs>
  <Tab title="Claude Code (CLI)">

    Run in terminal:

    ```bash
    claude mcp add --transport http hacktron https://mcp.hacktron.ai/mcp
    ```

    Then authenticate the connection:

    1. Start Claude Code in your project.
    2. Type `/mcp`, select `hacktron`, and choose **Authenticate**.
    3. Complete the Hacktron browser sign-in.

    <Accordion title="Prefer using an API key?">
      Create an organization API key — see [Authentication](/api-reference/authentication#creating-an-api-key). Grant `read` & `write` access to let your assistant triage findings.

      Run in terminal:

      ```bash
      claude mcp add --transport http hacktron https://mcp.hacktron.ai/mcp --header "Authorization: Bearer hacktron_your_key_here"
      ```

      <Warning>
        An API key is a long-lived secret. Store it in your client's secret settings, never commit it to source control, and grant the narrowest scope your workflow needs.
      </Warning>
    </Accordion>

  </Tab>
  <Tab title="Claude Desktop">

    Add to `~/Library/Application Support/Claude/claude_desktop_config.json`:

    ```json
    {
      "mcpServers": {
        "hacktron": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "https://mcp.hacktron.ai/mcp"]
        }
      }
    }
    ```

    Restart Claude Desktop to apply changes.

    When Claude Desktop connects to Hacktron for the first time, complete the Hacktron browser sign-in. If the prompt does not appear, open Claude Desktop's MCP server settings and reconnect `hacktron`.

    <Accordion title="Prefer using an API key?">
      Create an organization API key — see [Authentication](/api-reference/authentication#creating-an-api-key). Grant `read` & `write` access to let your assistant triage findings.

      ```json
      {
        "mcpServers": {
          "hacktron": {
            "command": "npx",
            "args": ["-y", "mcp-remote", "https://mcp.hacktron.ai/mcp", "--header", "Authorization: Bearer hacktron_your_key_here"]
          }
        }
      }
      ```

      <Warning>
        An API key is a long-lived secret. Store it in your client's secret settings, never commit it to source control, and grant the narrowest scope your workflow needs.
      </Warning>
    </Accordion>

  </Tab>
  <Tab title="Cursor">

    Add to `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "hacktron": {
          "url": "https://mcp.hacktron.ai/mcp"
        }
      }
    }
    ```

    Reload Cursor after saving (`Cmd+Shift+P` → **Reload Window**).

    When Cursor prompts you to authenticate `hacktron`, complete the Hacktron browser sign-in. You can also open Cursor's MCP settings, select `hacktron`, and start authentication from there.

    <Accordion title="Prefer using an API key?">
      Create an organization API key — see [Authentication](/api-reference/authentication#creating-an-api-key). Grant `read` & `write` access to let your assistant triage findings.

      ```json
      {
        "mcpServers": {
          "hacktron": {
            "url": "https://mcp.hacktron.ai/mcp",
            "headers": {
              "Authorization": "Bearer hacktron_your_key_here"
            }
          }
        }
      }
      ```

      <Warning>
        An API key is a long-lived secret. Store it in your client's secret settings, never commit it to source control, and grant the narrowest scope your workflow needs.
      </Warning>
    </Accordion>

  </Tab>
  <Tab title="Codex">

    Run in terminal:

    ```bash
    codex mcp add hacktron --url https://mcp.hacktron.ai/mcp
    ```

    Then authenticate the connection:

    ```bash
    codex mcp login hacktron
    ```

    Complete the Hacktron browser sign-in. In an interactive Codex session, type `/mcp` to check the server's connection and authentication status.

    <Accordion title="Prefer using an API key?">
      Create an organization API key — see [Authentication](/api-reference/authentication#creating-an-api-key). Grant `read` & `write` access to let your assistant triage findings.

      **1.** Add your API key to your shell profile (`~/.zshrc` or `~/.bashrc`):

      ```bash
      export HACKTRON_API_KEY=hacktron_your_key_here
      ```

      **2.** Register the server:

      ```bash
      codex mcp add hacktron --url https://mcp.hacktron.ai/mcp --bearer-token-env-var HACKTRON_API_KEY
      ```

      <Warning>
        An API key is a long-lived secret. Store it in your client's secret settings, never commit it to source control, and grant the narrowest scope your workflow needs.
      </Warning>
    </Accordion>

  </Tab>
  <Tab title="Antigravity">

    Add to `~/.gemini/config/mcp_config.json`:

    ```json
    {
      "mcpServers": {
        "hacktron": {
          "serverUrl": "https://mcp.hacktron.ai/mcp"
        }
      }
    }
    ```

    Click **Refresh** in the MCP Servers panel to apply changes.

    Select `hacktron` in the MCP Servers panel and complete the Hacktron browser sign-in when prompted.

  </Tab>

## Tools

Each tool calls the same endpoint as the [REST API](/api-reference/introduction), with the same permissions. Viewers can read, members can change findings and set up pentests, and only organization admins can start a pentest.

### Scans and findings

| Name                  | Description                                      | REST endpoint                                                                  |
| --------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------ |
| `list_scans`          | List scans with severity breakdown               | [`GET /scans`](/api-reference/scans/list-scans)                                |
| `get_scan`            | Get details about a scan                         | [`GET /scans/{id}`](/api-reference/scans/get-scan)                             |
| `export_findings`     | Export a scan's findings as JSON, CSV, or SARIF  | [`GET /scans/{id}/findings/export`](/api-reference/scans/export-scan-findings) |
| `stop_scan`           | Stop a running scan or pentest                   | [`POST /scans/{id}/stop`](/api-reference/scans/stop-scan)                      |
| `list_findings`       | List findings across the organisation            | [`GET /findings`](/api-reference/findings/list-findings)                       |
| `count_findings`      | Count findings by severity, state and repository | [`GET /findings/counts`](/api-reference/findings/count-findings)               |
| `get_finding`         | Get details about a finding                      | [`GET /findings/{id}`](/api-reference/findings/get-finding)                    |
| `update_finding`      | Update a finding's state or severity             | [`PATCH /findings/{id}`](/api-reference/findings/update-finding)               |
| `add_finding_comment` | Post a comment on a finding                      | [`POST /findings/{id}/comments`](/api-reference/findings/add-finding-comment)  |

### Pentests

| Name                     | Description                                          | REST endpoint                                                                       |
| ------------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `list_repositories`      | List connected repositories                          | [`GET /repos`](/api-reference/repos/list-repos)                                     |
| `request_archive_upload` | Get a URL to upload a code archive                   | [`POST /archives/uploads`](/api-reference/archives/request-archive-upload)          |
| `create_pentest_draft`   | Set up a pentest of code, optionally with live sites | [`POST /pentests`](/api-reference/pentests/create-pentest)                          |
| `update_pentest_draft`   | Change a pentest that hasn't started                 | [`PATCH /pentests/{id}`](/api-reference/pentests/update-pentest)                    |
| `verify_pentest_login`   | Check that Hacktron can sign in to each site         | [`POST /pentests/{id}/login-checks`](/api-reference/pentests/check-pentest-logins)  |
| `estimate_pentest`       | Price a pentest                                      | [`POST /pentests/{id}/estimate`](/api-reference/pentests/estimate-pentest)          |
| `get_cost_estimation`    | Get a pentest cost estimate                          | [`GET /cost-estimations/{id}`](/api-reference/cost-estimations/get-cost-estimation) |
| `get_credit_balance`     | Get the organisation's pentest credit balance        | [`GET /credits`](/api-reference/credits/get-credit-balance)                         |
| `start_pentest`          | Start a pentest and spend its credits (admins only)  | [`POST /pentests/{id}/start`](/api-reference/pentests/start-pentest)                |
| `discard_pentest_draft`  | Delete a pentest that hasn't started                 | [`DELETE /pentests/{id}`](/api-reference/pentests/discard-pentest)                  |

<Warning>
  To test a site signed in, your assistant sends the login details to Hacktron,
  where they're stored encrypted. Anything you type in the conversation also
  goes to your assistant's model provider, so use a test account.
</Warning>
